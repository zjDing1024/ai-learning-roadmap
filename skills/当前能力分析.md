# 当前能力分析

日期：2026-10-08。

## 已知事实

- 目标是长期建设公开 AI 工程作品集，覆盖基础、模型、论文、LLM/RAG/Agent 与部署。
- 当前首个项目提供可执行的 PyTorch 数学与行为验证，由 AI 助理实现和运行。
- 未收到用户的既有项目清单、教育/工作背景、每周可投入时间、Python/数学自测或 GPU 资源信息。

## 尚不能下结论

不能说用户“零基础”“已掌握 PyTorch”或“已达到某岗位要求”。选择阶段 1 是任务书要求及安全起点，后续根据自测调整深度。

## 最小诊断任务

1. 用 Python 写一个带输入检查的均方误差函数及三个测试。
2. 解释矩阵 X[N,D] 与 W[D,K] 的乘法结果，手算广播偏置的梯度。
3. 创建分支、修改一个测试、提交并解释 diff；不需要暴露任何私有项目。
4. 说明训练/验证/测试的职责，举一个数据泄漏例子。
5. 说明当前可用设备、是否有 GPU、希望优先申请的岗位与每周学习时间。

前四项是能力证据；第五项用于安排难度和节奏。没有回答不阻止助理继续准备可验证材料，但个人能力状态保持待确认。

## 当前作品的求职价值与缺口

首个增量能展示：对数值正确性、坏输入、可复现记录和文档边界的重视。缺口仍明显：数据是小型合成数据；只有 CPU 全批次回归；缺少真实任务、模块化训练、恢复、部署、资源分析和个人独立验证。它是训练工程项目的基础，不能单独作为成熟 ML Engineer 能力证明。

下一步先做自测和模块化训练，随后补 checkpoint 恢复与真实数据评估；不要为增加仓库数量跳到复杂 Agent 框架。
